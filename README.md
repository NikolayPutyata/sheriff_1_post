# Журнал передачі договорів — Telegram Mini App

Електронна заміна паперового журналу. Працівник ГШР вказує номер договору, обирає
себе зі списку і натискає **«Здав»**. Адміністратору одразу приходить повідомлення
від бота з кнопками **«✅ Отримано» / «❌ Відмовлено»**.

```
Телефон працівника / планшет            Адміністратор
  Telegram → Mini App (цей репозиторій,    ▲ повідомлення бота з кнопками
  Vercel)                                  │
     │  HTTPS + підписані дані Telegram    │
     ▼                                     │
  Сервер Хелпера (AUTO_WORD_GENERATOR, DigitalOcean)
     src/journal/ — API /api/journal + бот + MongoDB
```

Цей репозиторій — **лише фронт**. Сервер — модуль `src/journal/` у репозиторії
`AUTO_WORD_GENERATOR` (див. там `docs/journal-setup.md`).

## Можливості

- **Посади.** Інженер/охоронник здає договори. Менеджер бачить договори на посту і забирає прийняті. Адмін керує всім.
- **Верифікація (ручна).** Новий телефон вводить свій нікнейм **з Telegram** (`@username`), ПІБ і посаду. Сервер звіряє нікнейм з підписаними даними Telegram, тож вигаданий не пройде. Потім людина пише адміну особисто, і адмін підтверджує або відхиляє. Інженер/охоронник після підтвердження автоматично потрапляє до списку працівників.
- **Здача.** Номер договору (базова перевірка: `№ 123 / 45` → `123/45`), повне найменування клієнта (обов'язково), ПІБ працівника зі списку з пошуком, дата й час автоматично.
- **Планшет.** Акаунт адміна або акаунт з `JOURNAL_KIOSK_TG_IDS`: ПІБ не підставляється, форма очищається через 10 с.
- **Адмін.**
  - «Журнал → На посту»: нові заявки (Отримано / Відмовлено), прийняті договори з вибором галочками → «🔔 Сповістити менеджера» (з підказкою, хто відповідав за клієнта) або «⚖️ ЮВ», заявки менеджерів «Забрати» з підтвердженням усіх або частини.
  - «Журнал → Історія»: Сьогодні / Вчора / Тиждень / Період, фільтри статусів, пошук, CSV у Telegram.
  - «Працівники»: додати, перейменувати, вимкнути.
  - «Доступи»: запити на верифікацію, виправлення ПІБ і посади, «Написати», закрити або відкрити доступ.
- **Менеджер.**
  - «На посту»: усі договори на посту (сповіщені вам — угорі), вибрати прийняті → «📦 Забрати».
  - «Мої»: заявки, що чекають адміна (можна скасувати), і договори «У мене».
- **Строк зберігання.** Договори у фінальному статусі («У менеджера», «Передано ЮВ», «Відмовлено») сервер видаляє через 3 місяці. Договори на посту лишаються.

## Деплой на Vercel

1. Vercel → **Add New → Project** → імпортувати цей репозиторій.
2. Налаштування збірки вже є у `vercel.json`, нічого міняти не треба.
3. **Environment Variables:** `VITE_API_URL` = `https://<адреса сервера Хелпера>/api/journal`, без `/` в кінці.
4. **Deploy**. Отриману адресу (напр. `https://sheriff-1-post.vercel.app`) вкажіть на сервері у змінній `JOURNAL_WEBAPP_URL`.

> Після зміни `VITE_API_URL` потрібен **Redeploy**: змінна вшивається у збірку.

## Розробка локально

1. Сервер: у `AUTO_WORD_GENERATOR` запустити з `NODE_ENV=development JOURNAL_DEV_AUTH=true` і рештою `JOURNAL_*` (порт 8080).
2. Тут:
   ```bash
   npm install
   npm run dev        # http://localhost:5173, /api проксіюється на :8080
   ```
   Поза Telegram зверху з'являється жовта DEV-панель для перемикання між адміном, працівником, планшетом і новим телефоном.

```bash
npm run typecheck
npm run build
```

## Структура

```
client/src/
  App.tsx              вкладки, перевірка доступу
  pages/AccessGate     верифікація нового телефона
  pages/SubmitPage     здача договору
  pages/MinePage       «Мої здачі»
  pages/JournalPage    журнал адміна: «На посту» / «Історія»
  pages/AdminOnPost    на посту: масові дії, заявки менеджерів, вибір менеджера
  pages/ManagerPages   менеджер: «На посту» і «Мої»
  pages/GuardsPage     працівники (адмін)
  pages/AccessPage     запити на доступ (адмін)
  lib/api.ts           запити до сервера (VITE_API_URL)
  lib/telegram.ts      Telegram WebApp SDK: тема, haptic, кнопка «Назад»
shared/src/            перевірка номера, ПІБ і нікнейму, статуси, типи API
```

Правила перевірки в `shared/src` мають дзеркало на сервері
(`AUTO_WORD_GENERATOR/src/journal/validation.js`, `statuses.js`). Змінюючи одне, змініть і друге.

Стек: Vite, React 19, TypeScript, Tailwind CSS v4, TanStack Query, zod.
